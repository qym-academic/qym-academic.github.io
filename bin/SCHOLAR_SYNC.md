# 论文自动同步

本机定时任务每周一、三、五 09:00（日本时间）抓取公开 Google Scholar 个人主页。GitHub Actions 的 `update-citations.yml` 仅保留手动诊断入口：GitHub 托管运行机器访问 Scholar 会收到 HTTP 403，不能作为可靠的数据源。

本机入口：`pwsh -NoProfile -File bin/sync_scholar_local.ps1`。它使用仓库内被 Git 忽略的 `.venv`（仅需 Beautiful Soup 和 PyYAML），要求开始时工作区没有未提交的已跟踪文件，先快进拉取 `origin/main`，成功抓取后仅提交引用数据和成果页。失败时停止并保留原有数据；需要本机开机、联网，且可以访问 Google Scholar。推送会触发网站部署。

作者页使用一次公开 HTML 请求取得引用统计和论文列表，同一轮任务复用成功抓取的列表；只对尚未收录的论文查询详情。网络/超时错误每项最多尝试两次，间隔 30 秒；引用统计单次上限 180 秒，论文同步单次上限 300 秒。失败后用一次直接 HTTP 请求区分 403/429、验证码页面、超时或预期内容缺失；不记录响应正文，不使用代理或绕过验证码。任何抓取失败都返回非零状态，不再把“本轮未更新”显示为成功；既有数据仍保留。

- 新期刊、会议论文分别加入成果页对应栏目。仅期刊论文按年份分组，实际出现新年份论文后才生成对应标题，不预建空年份。会议论文保持下方一个整体列表，不设年份小标题；编号在各栏目内递增。
- 保留已有人工条目（作者星号、封面、高被引、邀请论文、会议时间等）。已有条目不被 Scholar 数据覆盖；同标题或 DOI 的记录不重复加入。
- 新记录采用完整作者、期刊或会议、年份、可用卷期页码、论文链接；本人姓名加粗，期刊/会议沿用页面粗斜体样式。
- Scholar 不提供可靠的通讯/共同一作或封面信息，新记录不推测这些标记，需要人工补充。会议的举办日期与发表日期不同，不从发表年份猜测举办日期。
- 只导入能明确识别为期刊或会议、具有完整作者与有效链接的记录。缺字段或抓取受阻时保留既有页面，在 Actions 摘要中报告暂缓记录。每轮最多补查 20 个候选详情。
- Google Scholar 抓取可能限流，不保证每轮成功，也不会删除 Scholar 暂时缺失的旧成果。

验证：`python -m unittest discover -s test -p 'test_scholar_publications.py'`。
仅整理已有年份：`python bin/update_scholar_publications.py --normalize-only`。
